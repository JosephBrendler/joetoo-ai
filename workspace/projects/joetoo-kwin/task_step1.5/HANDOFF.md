## Objective and bounded implementation plan

Make `DESKTOP|sdl-freerdp|rdp|rdp://USER@HOST[:PORT][|LAYER]` a first-class configured recipe: offline validation → existing `-o` confirmation/serial launch → positive persistent-viewer UUID registration → immediate exact-UUID placement and frame verification → next entry → existing per-desktop `under → panel → over` stack/focus transaction → next desktop cohort. No GDM-readiness wait, second manual placement, new geometry allocator or repeated KWin geometry repair.

**Module policy:** Prefer **one production RDP frontend/persistent-worker executable** analogous to VNC, by extending the existing broker-imported `libexec/joetoo_kwin_rdp_launch.py` *if compatible*. Add `joetoo_kwin_rdp_target.py` for offline target/settings parsing. If expansion of the existing module causes substantial churn, propose a narrow alternative for approval first. The existing `tools/joetoo-sdl-*.py` scripts remain **diagnostic harnesses**; production `-o` must not execute or chain them. Cross-client VNC/RDP normalization is deferred to Version 2.

**Settled policy:** optional per-recipe RDP port (default 3389); configurable remote resolution `1024×768`, smart sizing (`$TRUE`), initial client `800×600`, with planner-owned *outer-frame* geometry. User-facing `rdp_windowing_backend=auto|wayland|x11`: implement verified automatic detection only if simple, otherwise explicit host selection (SDL implementation-specific environment remains internal). Configurable **300000 ms (five-minute)** default for RDP viewer-registration and TigerVNC viewer-readiness waits. On known-clean pre-registration timeout/failure, terminate only owned pending work, confirm cancellation/cleanup, report and continue; never bypass Busy or unresolved owner/transaction state. Preserve historical `presence=missing` slot reservations unless **positive termination and release-with-history** can be added narrowly and safely under separate review. Broker restart preserves existing clients/workers but currently loses the in-memory managed registry; no auto-recovery in Increment 4. Option D concurrent missions, retry semantics and common VNC/RDP lifecycle framework are Version 2.
