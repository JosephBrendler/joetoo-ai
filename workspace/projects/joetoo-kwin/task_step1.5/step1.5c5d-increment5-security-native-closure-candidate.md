## Production policy found in source

### Exact launch and endpoint contract

`configured_argv()` reuses the fixed development builder, replacing only the two size arguments. After `launch_registration()` fixes the executable, the child receives:

```text
/usr/bin/sdl-freerdp
/v:HOST:PORT                      (IPv6 is bracketed)
/u:USER
/t:joetoo-rdp-<64 hexadecimal digits>
/log-level:INFO
/log-filters:com.freerdp.client.SDL:DEBUG
/size:REMOTE_WIDTHxREMOTE_HEIGHT
/smart-sizing:CLIENT_WIDTHxCLIENT_HEIGHT  (or /smart-sizing:off)
```

The configured defaults are remote 1024×768 and client 800×600. There is **no** `/cert:deny`, `/cert:ignore`, `/cert:tofu`, `/cert:name`, `/sec:`, password, client `.rdp` file, gateway or arbitrary-switch argument. `target()` preserves DNS spelling and validates/defaults port 3389; IP literals are canonicalized. An IP target needs an applicable certificate identity; DNS SAN validation must not be assumed for an IP. No shell evaluates the argv.

### Certificate and negotiation delegation is material

FreeRDP [tls.c, `tls_verify_certificate()`](https://github.com/FreeRDP/FreeRDP/blob/3.32.1/libfreerdp/crypto/tls.c#L1757), especially 1844–1895, checks chain and hostname, then permits client trust configuration/known-host handling and callbacks when verification does not succeed. SDL registers its own callbacks in [sdl_context.cpp:53–55](https://github.com/FreeRDP/FreeRDP/blob/3.32.1/client/SDL/SDL3/sdl_context.cpp#L53). [sdl_dialogs.cpp:445–523](https://github.com/FreeRDP/FreeRDP/blob/3.32.1/client/SDL/SDL3/dialogs/sdl_dialogs.cpp#L445) offers **permanent**, **temporary** (Return-key default), and **cancel** trust choices. Consequently, “no warning” can also reflect previously stored acceptance; it is not independently proof of current CA validation. The manual `/cert:deny` evidence does not change production argv.

FreeRDP [settings.c:975–981](https://github.com/FreeRDP/FreeRDP/blob/3.32.1/libfreerdp/core/settings.c#L975) enables extended/NLA/TLS/**legacy RDP** negotiation. [nego.c:698–769](https://github.com/FreeRDP/FreeRDP/blob/3.32.1/libfreerdp/core/nego.c#L698) contains NLA→TLS and TLS→RDP fallback paths. This establishes capability, **not** an observed downgrade in any accepted run. Recipes cannot inject a downgrade or certificate-bypass flag, but that does not make the default client policy strict. Local username/password handling and trust decisions remain FreeRDP responsibilities.

**Required policy disposition:** accept delegated FreeRDP negotiation and operator-managed trust explicitly, with the above limits, or require a separately authorized small argument-policy correction. Native testing cannot prove the existing client enforces an absent TLS/NLA-only or strict-certificate flag. No previously approved strict production policy was found against which to label this automatically an implementation defect. The evidence gap must not be closed by silently treating interactive exceptions as strict verification. If the maintainer requires unconditional certificate refusal or prohibits legacy negotiation, source correction is required before closure; another successful GDM test cannot satisfy that requirement.

### Confidentiality and truthful outcomes

The supported recipe contains an account and endpoint, **not a password**. Those nonsecret identity values appear in the launch-plan table, `/v:`/`/u:` process arguments and preflight JSON; endpoint anonymity is not provided. Trusted executable Bash and the same user's process/environment are outside an untrusted-recipe sandbox.

`development_environment()` copies the parent environment, pins the backend, and controls WLOG layout/filter overrides; it is not a general credential-environment scrubber. Stock SDL may use inherited `FREERDP_ASKPASS` ([sdl_dialogs.cpp:135–160](https://github.com/FreeRDP/FreeRDP/blob/3.32.1/client/SDL/SDL3/dialogs/sdl_dialogs.cpp#L135), [passphrase.c:329–336](https://github.com/FreeRDP/FreeRDP/blob/3.32.1/libfreerdp/utils/passphrase.c#L329)). The wrapper does not configure that helper or store passwords, but cannot claim to forbid all inherited client credential facilities. Use the ordinary trusted environment without a credential helper for the closure observations.

Client stdout/stderr are retained privately as `stdout.log`, with integrity/size checks; worker control/status files are private and nonce/process-bound. Raw client logs are **not guaranteed sanitized** or appropriate for public evidence. The size budget is checked, not a filesystem quota: an already registered viewer is preserved with degraded supervision if subsequent logging fails. This accepted behavior is independent of certificate trust.

Broker registration proves local process/FD/source/marker/UUID ownership; placement independently verifies desktop and frame. `configured_worker()` and `configured_frontend()` preserve `remote_session=unverified`, even for `state=completed`. They do not measure TLS ciphers, NLA success, GDM login or usable remote session. Before registration, certificate refusal/authentication failure/cancel/exit can end the pending mission: only verified broker terminal state **and** owned-process cleanup permit continuation. Unknown cleanup stops. After registration, placement/logging failure does not authorize sacrificing the viewer. Normal exit preserves the original record as missing, including its slot. Existing tests support these transitions; a client exit code alone does not identify a security failure or remote logout cause.
